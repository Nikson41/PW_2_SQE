# 🤝 CONTRIBUTING

Дякуємо за бажання долучитися до розвитку проєкту **«Хрестики-нулики»**.

---

## Як почати роботу

### 1. Клонування репозиторію

### Відкрийте репозиторій на GitHub

Перейдіть за посиланням:

[https://github.com/USERNAME/REPOSITORY.git](https://github.com/Nikson41/PW_2_SQE.git)

Натисніть зелену кнопку **«<> Code»**.

### Оберіть зручний спосіб отримання проєкту

- **HTTPS** — скопіюйте посилання та використайте його у вашому Git-клієнті.
- **SSH** — використовуйте, якщо у вас налаштовані SSH-ключі для GitHub.
- **GitHub CLI** — підходить для роботи через командний рядок GitHub.
- **Download ZIP** — завантаження проєкту без історії комітів та системи контролю версій.
- **Open with GitHub Desktop** — відкриття репозиторію через застосунок GitHub Desktop.

### 2. Створення нової гілки

```bash
git checkout -b feature/new-feature
```

Для назв гілок рекомендується використовувати:

```text
feature/...
fix/...
docs/...
test/...
refactor/...
```

---

### 3. Внесення змін

Внесіть необхідні зміни до програмного коду або документації.

---

### 4. Перевірка роботи програми

Запустіть програму:

```bash
python main.py
```

---

### 5. Запуск тестів

Перевірте працездатність тестів.

#### unittest

```bash
python -m unittest test_tictactoe.py
```

#### pytest

```bash
pytest -v
```

---

### 6. Створення коміту

```bash
git add .
git commit -m "feat: додано нову функцію"
```

Приклади типів комітів:

```text
feat
fix
docs
test
refactor
style
```

---

### 7. Відправка змін

```bash
git push origin feature/new-feature
```

---

### 8. Створення Pull Request

Після відправлення змін створіть Pull Request через GitHub.

---

## Стиль коду

Рекомендується:

* використовувати відступи у 4 пробіли;
* додавати коментарі до складних ділянок коду;
* використовувати зрозумілі назви змінних;
* дотримуватися рекомендацій PEP 8.

---

## Повідомлення про помилки

Якщо знайдено помилку:

1. Відкрийте вкладку Issues.
2. Створіть новий Issue.
3. Опишіть проблему.
4. За можливості додайте скріншоти.

---

## Тестування нових функцій

При додаванні нового функціоналу рекомендується:

* створити unittest-тести;
* створити pytest-тести;
* переконатися у відсутності помилок перед створенням Pull Request.

---
